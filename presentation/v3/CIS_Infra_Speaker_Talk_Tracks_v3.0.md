## CIS Infra 02 Agent Governance Operations v3.0

**Slide 1. Cover**

Say: This offering answers three questions every CIO now asks: what agents do we have, are they actually used, and can we stop one that misbehaves. Microsoft now sells Agent 365 as the control plane, so we configure that first and build only what it does not cover.

Likely question: Did Agent 365 make this offering redundant?
Answer: No. It gives the registry and policy layer. Customers still need it configured, joined to runtime evidence, operated, and backed by a tested containment path across several layers.

**Slide 2. Summary: configure the control plane, then fill gaps**

Say: Version 2 proposed building our own agent registry. Microsoft has since shipped Agent 365, so the honest position is: configure Microsoft’s control plane first, then add what it lacks, mainly usage evidence and a cross-layer stop path that we prove before we sell it.

Likely question: What do customers need to buy from Microsoft?
Answer: Agent 365 at 15 dollars per user per month, or Microsoft 365 E7 which includes it. Basic inventory is included with any Microsoft cloud subscription. We check this in the assessment.

**Slide 3. Why now, and who buys**

Say: Two things changed this year. Microsoft shipped a real agent control plane, and its own documentation confirms stopping an agent does not end work already running. That combination creates demand for configuration plus a tested stop path.

Likely question: Is there market evidence?
Answer: These are sourced product and regulatory facts, not demand statistics. The validation asks account teams for three qualified candidates.

**Slide 4. Where this offering sits, and the Microsoft ecosystem**

Say: Agent governance sits between the gateway and managed operations. Copilot Studio agents are now in scope as a covered runtime, governed through Agent 365; Microsoft 365 Copilot itself stays with our M365 and D365 teams.

Likely question: Who administers Copilot Studio?
Answer: The Power Platform team keeps environment administration. We bring its agents into the catalogue, containment and cost views.

**Slide 5. What CIS Infra provides, and what it does not**

Say: We configure and integrate; we do not own agent behaviour or security operations. Note the Power Platform team keeps Copilot Studio administration.

Likely question: What if the customer has no Agent 365 licence?
Answer: Then the custom gap layer carries more of the catalogue, and the assessment shows the cost trade-off of licensing versus building.

**Slide 6. Architecture: native first, custom only for gaps**

Say: Read it bottom-up. The runtimes are where agents live, including Copilot Studio. Layer one is Microsoft’s control plane: Agent 365, the Foundry Control Plane, Entra agent identities, Defender and Purview. Layer two is the runtime evidence. Only layer three, in purple, is what we build: reconciliation, the usage catalogue and the containment orchestrator.

Likely question: Why still build layer three?
Answer: Because the native tools do not join deployment records to usage evidence across all runtimes, and none claims a cross-layer stop with verification. We prove that in the proof of concept.

**Slide 7. Configure first: what Microsoft gives, what we add**

Say: Left is what Microsoft provides once licensed and configured. Right is what we still add. The rule for every customer: if a native feature covers it, we configure it; we only build the right-hand column.

Likely question: Will the right-hand column shrink over time?
Answer: Yes, as Microsoft adds lifecycle actions. That is why we keep the custom layer thin and replaceable.

**Slide 8. What it takes: effort, time and fee bands**

Say: Five packages, sold in sequence. Most customers start with the assessment and the configuration package. The proof of concept is a gate: we do not sell the containment build until it passes.

Likely question: Why so wide?
Answer: Number of runtimes and clouds, licence position and telemetry quality drive the range.

**Slide 9. Risks that decide success, and how we handle them**

Say: The biggest risk is promising a stop we have not tested, which is why the proof of concept is a gate.

**Slide 13. No telemetry is not proof of no usage**

Say: The catalogue sorts every agent into one of six states. The key rule: missing telemetry is its own state and never counts as dormant, so we never delete a live agent by mistake.

Likely question: Who decides to retire an agent?
Answer: The business owner, after review. Never automatic.

**Slide 14. Custom gap layer: detailed reference architecture**

Say: Use this slide to explain "Custom gap layer: detailed reference architecture". Steps: (1) deployment pipelines write agent ID, version, environment, owner and endpoint into the registry at release; (2) a scheduled Function App queries Foundry Control Plane for supported agents and Resource Graph for hosting resources and tags; (3) it queries Application Insights and Log Analytics for last run, run count, errors and tokens per agent ID; (4) it reconciles and writes status to Cosmos DB, flagging unmatched resources as orphaned and records without telemetry as telemetry unknown; (5) Workbooks presents the catalogue and review queues; (6) Azure Monitor alerts route telemetry-health and dormancy reviews to owners. Identity: the reconciliation job uses a managed identity with Reader on in-scope subscriptions and read access to the workspaces; it has no write access to agent runtimes.

**Slide 15. How each source contributes, and where it stops**

Say: Use this slide to explain "How each source contributes, and where it stops". Native behaviour verified against Microsoft Learn (Foundry Control Plane manage agents, updated 2026-07-15). Inventory columns cover the last month. Metrics and traces are collected only after observability is configured, with up to 15 minutes propagation.
